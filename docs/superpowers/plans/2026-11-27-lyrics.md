# Lyrics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tapping the album art opens a lyrics screen showing LRCLIB lyrics, highlighted line by line in sync with Spotify. The Mac helper fetches the lyrics and sends them over a new BLE characteristic.

**Architecture:** Protocol v1.1 adds an optional chunked **Lyrics** characteristic, built like Art.
- **Firmware:** decodes it in `lib/core` (pure, native-tested), keeps current and pending lyrics per source slot in `NowPlaying` as it does art, and renders a second UI view toggled by a tap on the art.
- **Mac helper:** parses LRC and LRCLIB JSON in `HelperCore` (pure, tested), adds Lyrics to `SendPlanner`/`WriteQueue`, and fetches in the app target with URLSession.

**Tech Stack:**
- Firmware: PlatformIO pioarduino 55.03.312-1, LovyanGFX 1.2 (efontJA), NimBLE-Arduino ^2.5.2, Unity native tests with ASan/UBSan.
- Mac helper: Swift 6.3 SwiftPM (CLT only) with swift-testing; URLSession and JSONDecoder.

**Spec:** `docs/superpowers/specs/2026-11-27-lyrics-design.md`. Base design: `docs/superpowers/specs/2026-11-26-now-playing-display-design.md`. Wire format: `protocol/PROTOCOL.md`, which Task 1 extends and which is binding.

## Global Constraints
- Work on the branch `feat/lyrics` off `main`.
- **Lyrics characteristic:**
  - UUID `6e0a0006-7b5d-4c1e-9f3a-2d8c5b1e4a70`, WRITE_NR | WRITE, max 512 bytes per write.
  - Header `0x01, u32 track_id, u32 total_len, u8 kind` (exactly 10 bytes, written with response). Data `0x02, u32 track_id, u32 offset, bytes…`.
  - `kind`: 0 none, 1 synced, 2 plain, 3 instrumental. Kinds 0 and 3 have `total_len` = 0 and no data.
  - Body ≤ **16384** bytes: lines of `u32 time_ms, u8 len, len bytes UTF-8`, with len ≤ **200** and the cut on a UTF-8 boundary. Times are non-decreasing. Plain lyrics have every time 0. An empty line shows as "♪".
- **Compatibility:** helpers skip lyrics when the characteristic is missing (old firmware), and old helpers never write it. The display shows "Looking for lyrics…" for **10 s** after a track starts, then "No lyrics".
- **Send order:** Meta → Art → Lyrics → State on reconnect (`resendAll`). On a track change, Lyrics are sent after the art fetch has finished or failed.
- **LRCLIB:**
  - `GET https://lrclib.net/api/get?track_name=&artist_name=&album_name=&duration=<s>`. On a 404, make one `GET https://lrclib.net/api/search?track_name=<clean title>&artist_name=<first artist>`.
  - User-Agent `MusicDisplay/1.0`, timeout **8 s**.
  - Cache only definite results (last **50** URIs). A network error sends kind 0 without caching it.
- **Match rule:** the hit's artist must contain the first artist, case- and diacritic-insensitively. Its duration must be within **3 s**. Synced beats plain, and a closer duration wins ties.
- **Title cleaner** strips a trailing ` - Remastered…`/` - Remaster…`/` - … Remaster(ed)…`, ` - Live…`, ` - Radio Edit`, ` - Single Version`, ` - Mono…`/` - Stereo…`, and ` (feat. …)`/` (with …)`/` [feat. …]`, case-insensitively.
- **LRC offset:** a positive `[offset:ms]` shows lyrics earlier: `t = max(0, t − offset)`.
- **Mac timing:** AppleScript poll while playing **2 s** (was 5). `SendPlanner.seekToleranceMs` **750** (was 2000). State interval stays 5 s.
- **Lyrics screen:**
  - Previous line dim (efontJA_12), current line white (efontJA_16, wraps to ≤ 2 rows), and the next two lines dimmed.
  - The line-change slide lasts 150 ms and is computed from the time since the change, never a blocking delay.
  - Plain lyrics scroll in proportion to position/duration and show an "unsynced" tag in the status row.
  - Kind 3 shows "♪ Instrumental". Kind 0 shows "No lyrics for this song".
- **View:** the lyrics view persists across track changes and drops to Main when there's no active source. A view-toggle tap never sends a command.
- **Tests:**
  - Firmware: `cd firmware && $PIO test -e native` (all suites).
  - Mac: `mac-helper/scripts/test.sh`.
  - Firmware build: `cd firmware && $PIO run -e es3c28p`. Upload: `$PIO run -e es3c28p -t upload --upload-port /dev/cu.usbmodem101`.
  - `PIO=/private/tmp/claude-501/-Users-rayyan-Projects-music-display/0326c728-820e-463f-83f0-86dfb5e87f90/scratchpad/pio-venv/bin/pio`. If it's missing, run `pipx install platformio` and use `pio`.

## Review Focus
1. **Lyrics for the next track arrive before its State** (Spotify skipping fast): they must be held as pending and promoted, never shown on the old track. Test: `lyricsForUpcomingTrackPromotedOnState` (Task 2).
2. **A malformed or oversized body** (a len running past the end, len > 200, total > 16384, decreasing times): it's rejected with no crash under ASan, and the display keeps "Looking…" or "No lyrics". Tests: `lyricsBodyRejectsOverrun`, `lyricsHeaderRejectsOversize` (Task 1).
3. **A seek backwards or a pause on the lyrics screen:** the highlighted line follows the position back and freezes while paused. Test: `currentLineFollowsBackwardSeek` (Task 2).
4. **Huge lyrics or very long lines** (emoji, CJK): the encoder stays ≤ 16384 bytes by dropping whole lines from the end, and cuts lines ≤ 200 bytes on a UTF-8 boundary. Tests: `lyricsEncoderTruncatesTo16K`, `lyricsLineCutOnUTF8Boundary` (Task 5).
5. **A Spotify title that LRCLIB names differently, or a wrong-artist search hit:** the cleaner and matcher pick the right hit and reject a same-title song by another artist or with a duration more than 3 s off. Tests: `cleanTitleStripsRemaster`, `bestRejectsOtherArtist`, `bestRejectsDurationOff` (Task 5).

    2. `await artTask?.value`.
    3. Cache non-nil results.
    4. Send `planner.lyricsReady(uri:, result: r ?? LyricsResult(kind: .none, lines: []))`.
